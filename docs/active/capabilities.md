# 当前能力与验证边界

> 更新：2026-11-26。代码存在、隔离测试、真实应用验证和用户任务闭环是不同证据，不得互相替代。公开文档不记录具体客户账号、资产、日志或现场运行明细。

## 首次接入与智能体

| 能力 | 当前实现 | 验证与边界 |
|---|---|---|
| 云账号保存后自动处理 | 正常账号路径有凭证探测、资产同步、默认规则播种和统一 Onboarding Run | 隔离验证；既有只读身份另完成真实探测和限定同步，不等于新账号全自动编排已做真实验收 |
| 云资产发现 | 阿里云注册 ECS、RDS、Redis、SLB、OSS、CDN、WAF、ACK、ES 等采集器 | 已在限定账号与产品范围做真实同步；不代表所有账号、地域或其他云厂商 |
| 统一接入任务 | 一账号一条持久 Run，向导、云账号页和智能体共享状态，重接递增 attempts；刷新、切入口和网络恢复继续原 Run，晚到响应及同 Run 旧 attempt 不覆盖新状态 | 跨入口隔离浏览器验证通过；结构化深链可恢复同一 Run；`init_done` 只控制向导路由，不等于 ready；真实首次使用待验 |
| 简洁任务结果卡 | 一句结论、最多三个关键数字、最多三个阻塞摘要和一个主动作；完整能力、失败清单、真实范围、证据和时间窗可展开 | 隔离浏览器与定向计算样式验证通过；凭证失败、多范围重试、非管理员和重复实时卡已有反例；深链目标页具体分析仍按各页面能力验收 |
| 受保护凭证与无模型降级 | 向导和账号页复用受保护表单，退出清空明文；智能体新账号只返回表单引用，无模型仍显示确定性任务卡 | 隔离验证伪造秘密不转发、明文不进入浏览器持久存储、低权限角色无管理假按钮；取消、关闭公有云和创建响应丢失均有反例；未使用或保存真实凭证做该项测试 |
| 真实就绪口径 | 凭证、资产和默认规则证据齐全才 ready，产品失败和证据缺口显式保留 | 本机与隔离验证；不保证指标、账单和变更即时就绪 |
| 智能体与工作流 | 会话、只读工具、结构化白名单、确认、审计和回滚 | 有代码与隔离回归，不代表所有回答均经真实场景验收 |
| 占位凭证 | 通用提示与账号 API 拒绝明确占位值 | 只拦截已知模式，不替代真实云端鉴权 |

## SLS、拓扑与业务归属

| 能力 | 当前实现 | 验证与边界 |
|---|---|---|
| SLS 查询源与账号绑定 | 有效阿里云凭证可形成隐式源；绑定后凭证冲突、账号停用或解密失败 fail closed | 限定账号完成 CDN、CLB 与 5xx 内容检索，不代表其他地域或腾讯云 |
| Project/Logstore 枚举 | Project 分页直至结束，Logstore 完整请求，失败保留范围与原因 | 限定账号有真实枚举证据；未配置索引的范围明确失败，不计为成功 |
| 日志角色识别 | 近 24 小时最多 5 条样本，只保留派生特征；未知角色不可采纳 | 限定账号存在未知角色；原始日志不落 Run、审计或模型 |
| 集中确认与账号隔离 | 唯一高置信应用/CDN 候选才自动预选，SLB 多选且人工选内外层，切账号丢弃慢响应 | mock 与真实浏览器定向验证；应用/CDN 仍各一个主目标 |
| 采纳验证与持久化 | 账号级目标必须来自已发现且角色匹配的可采纳候选；采纳后以同账号、endpoint 和已确认字段映射执行消费查询，失败恢复旧配置 | 新链路隔离回归通过；既有外层 CLB + CDN 有真实证据，新消费链真实首次使用待验 |
| 中断恢复 | 启动时把遗留 running 项收割为可重试失败，不自动访问云 | 隔离验证；验证时没有遗留运行项 |
| 第一次巡检价值 | 采纳 CLB 后聚合 5xx 并按实例拆分事实 | 限定巡检有真实只读证据；未生成日报或外发通知 |
| SLB 链路推导 | 依据 Host、Upstream、转发规则和 ECS IP 生成带证据链路 | 确定性规则，不等于所有拓扑已做真实内容验收 |
| 业务归属建议 | 只消费已确认日志流量边和精确业务标签，未知或共享冲突不自动归属 | 真实只读 planner 未生成、确认或合并真实映射 |
| 草稿确认与生效 | 自动结果只落 draft，人工逐条确认后进入公共归属解析 | 隔离与 mock 浏览器验证，不证明真实业务语义正确 |

## 模型走查、画像与变更

| 能力 | 当前实现 | 验证与边界 |
|---|---|---|
| 模型主动只读走查 | 模型在受控循环中选择 GET 和浏览器动作，成功需内容断言、证据引用和独立回放 | 隔离与真实模型限定页面验证；不是预设脚本总结，也不覆盖所有页面 |
| 走查安全 | 阻断非 GET、任意外域、敏感 query 和原始日志；模型不生成可执行 SQL/PromQL/命令 | 隔离负向验证；不替代确定性质量门 |
| 行为画像上下文 | 进程看整机 CPU+内存，URL 看唯一映射、逐后端 CPU 和对应 RT；窗口与阈值可配置 | 隔离回归与限定真实只读裁决；未核实不当作正常 |
| 画像异常生命周期 | 保留 stable / drift / unverified，独立错误、DB、成本异常不被资源稳定抑制 | 隔离覆盖；缺证据不自动恢复或抬基线 |
| 通用拉取变更源 | 统一 fetch、注册表、标准化批次、账号编排、去重和持久化 | ActionTrail 有真实单页只读证据；腾讯云/AWS/自建只有扩展契约 |
| webhook | 保留推送事件模型 | 不伪装为拉取 adapter |

## 成本

| 能力 | 当前实现 | 验证与边界 |
|---|---|---|
| 本地只读成本洞察 | 显式账号和日期；默认最近 30 天截至昨日；统一覆盖、日成本、订单/退款、排行、异常、首次观察和三类建议，带历史证据 | 隔离内容断言通过；GET 不触发云同步、通知、异常生命周期写入或 ORM 账单修改；无采购/SKU/节省金额；真实成本任务待验 |
| 成本首屏与智能体三个答案 | 首屏先给花费、异常和下一步，再展示同源图表与排行；原始明细/导出显式继承账号、产品和实例；点击智能体直接按结构化账号和起止日期运行确定性工作流并持久化到会话 | 工作流、会话恢复与隔离浏览器验证通过；覆盖模型不可用、低权限、无数据、真实零费用、部分覆盖、未归属、晚到/错误响应、失败重试、产品级下钻和高级页签；限定本机联调通过；真实账号原始账单对账和目标新手走查仍待验 |
| 费用拆解 | 产品、实例、计费场景、趋势和部分 CDN 下钻 | 有既有实现与功能回归，不等于所有账单场景已真实验证 |
| 成本异动 | 周期基线、中位数/MAD、样本充分性和对账 | 有既有实现与测试 |
| 资源包池与续购 | 抵扣池、余量预测、采购量粗算和续购建议 | 账号隔离与健康措辞仍有静态风险，不能视为已解决 |
| 具体采购决策 | 可建议部分包类型和容量 | 缺账号、地域、SKU、实际价格、优惠资格和到期浪费完整核算 |
| 预计净节省 | 部分金额是耗尽前后按量费用差及外推 | 不能当作扣除采购成本后的确定净节省 |
| 购买后复盘 | 用后续快照和账单核对抵扣与实际节省 | **未实现完整闭环；相关新增实现已回滚，暂停等待新预期** |

## 已做限定真实验证的应用集成

指定测试环境曾对 Prometheus、VictoriaMetrics、Loki、Elasticsearch 和 Gitea 完成版本探测、只读查询或 webhook 的限定场景验证。不能据此宣称：

- 外部 Prometheus/VM 已进入内置告警、巡检、画像或诊断统一查询；
- 所有日志语义和告警闭环已经打通；
- 所有 Git 平台和全部事件类型均已支持。

## 必须保留的边界

- VictoriaLogs 是部署预留，不是已实现的统一日志查询能力。
- K8s 升级是单控制面实验节点的受限路径，多节点 fail-closed，不是完整集群升级。
- InfluxDB、Graphite、OpenTSDB、自定义 HTTP 等部分类型只有登记或探活，没有统一查询适配。
- 火山、百度、华为、AWS、Azure 等厂商没有当前真实连通与资产同步证据。
- 国产 CPU/OS 的兼容声明缺少当前系统级验证，不得写成已真实验收。
- 当前部署是单机，HA 是路线图。

## 完成口径检查表

1. 用户从哪个入口开始，最终得到什么结果？
2. 自动完成哪些步骤，用户仍必须做什么，为什么？
3. 成功、部分失败、无权限、无数据、无证据分别怎样显示？
4. 是设计、代码、隔离验证还是真实内容级验证？
5. 是否仍要求用户跨页面补步骤或理解底层字段？
6. 失败能否恢复，重试是否幂等，是否可能重复执行外部动作？
7. 文档和界面承诺是否超出证据？
