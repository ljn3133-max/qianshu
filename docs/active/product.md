# 产品基线

> 更新：2026-11-17。本文定义产品目标与人机边界，不是功能完成声明。

## 一句话定位

**千枢让不懂云产品和 AIOps 的用户，也能在必要授权后，由 AI 完成环境接入、数据理解、日常运维和成本优化；人只做无法替代的决策。**

千枢的安装价值不是再提供一套需要学习的控制台，而是把运维专家的判断和劳动产品化。如果用户不借助平台也能轻松完成同一任务，这个功能就没有形成产品价值。

## 核心任务链

```text
安装 → 授权接入 → 自动发现与理解 → 验证真实可用
     → 获得第一次诊断或成本价值 → 日常托管
```

页面用于查看证据和高级配置，不应成为新手必须顺序学习的操作手册。安装向导、智能体和管理页可以入口不同，但必须消费同一任务、阶段和就绪结果。

## 核心原则

### 1. AI 接管工作，不只生成解释

AI 默认承担发现、只读取证、分类推荐、步骤编排、失败重试、结果验证和进度恢复。默认回复只包含当前结论、关键数字、阻塞原因、一个主动作和可折叠证据。

“请去另一个页面配置”“接下来你需要执行六步”不是任务完成，除非该步骤确实必须由人授权或判断。

### 2. 先证明有数据且能回答，再显示就绪

以下事件都不等于用户任务完成：账号或数据源保存、探活成功、资产或日志目录枚举、工作流生成报告、页面渲染或只读接口回归通过。

就绪至少要能回答：有什么数据、覆盖多少、最新到什么时候、哪些失败或缺权限、平台用这些数据实际验证了什么。任一关键数据面失败时，不显示无条件的“全部完成”或“健康”。

### 3. 事实自动发现，语义依据证据，动作保留授权

- 只读发现和验证默认自动执行。
- 日志用途和业务归属必须有样本、字段、标签或链路证据；歧义集中确认，未知不猜测。
- 不按名称相似度自动绑定真实业务，不让 LLM 把推测冒充事实。
- 收费产品开通、购买、升级和外部写操作必须明确确认。
- 平台内配置变更复用结构化白名单、服务端确认、审计和回滚，不开放任意命令执行。

### 4. 新手不需要先成为云产品或成本专家

用户不需要预先知道 SLB、应用和 CDN 日志分别存在哪个 Logstore，也不需要先理解资源包抵扣池。无价格、无样本、无权限或无快照时，必须显示证据缺口，不能输出确定收益或健康结论。

### 5. 先把关键链路做透，再横向增加类型

优先完成首次接入、日志语义、日常诊断和成本决策闭环。新增登记型集成、更多菜单或通用聊天能力，不优先于这些任务。

## 人机分工

| 工作 | AI / 平台默认负责 | 用户保留 |
|---|---|---|
| 云接入 | 凭证探测、资源发现、分产品进度、权限诊断、失败重试 | 合规只读凭证及必要安全确认 |
| 日志理解 | 完整目录、字段指纹、样本分析、角色推荐、查询验证 | 低置信或业务专有语义确认 |
| 业务归属 | 汇总已确认的证据并生成草稿 | 确认无法自动确定的业务名称与边界 |
| 日常运维 | 巡检、异动取证、根因候选、影响面、复核 | 高风险处置和外部写入授权 |
| 成本优化 | 费用拆解、异常解释、包池预测、容量建议、核价与买后复盘 | 预算、采购和商业条件 |
| 产品打磨 | 任务走查、实现、真实浏览器与内容级验收 | 产品价值取舍、最终审美和封版 |

## 首次使用成功标准

1. 提交一次有效凭证后，不同入口展示同一个可恢复任务。
2. 主流程不要求用户跨页面寻找测试、同步、拓扑或初始化按钮。
3. 除凭证、安全确认和无法确定的语义外，不需要理解底层配置字段。
4. 已发现、未成功、无权限、无数据和待确认项完整可见，没有隐藏截断。
5. 至少用真实数据完成一次平台能力验证，而不只生成接入报告。
6. 重试只覆盖失败范围，不重复建账号、绑定目标或执行外部动作。

## 明确不做与不承诺

- 不承诺识别不存在、未采集或无权限读取的数据。
- 不承诺仅凭名称猜出全部日志角色或真实业务线。
- 不代替用户自动购买资源包、开通收费产品或修改外部云资源。
- 不用长篇解释代替自动执行，不把确定性脚本包装成 AI。
- 不为了全绿执行真实外部写用例或向真实通知渠道发送测试消息。
