# 数据源与集成

> 更新：2026-11-17。探活成功、代码适配、真实查询验证和用户任务闭环必须分开描述。

## 接入入口

| 类型 | 主要入口 | 就绪判断 |
|---|---|---|
| 云账号 | 安装向导、云账号管理、智能体 | 凭证、资产、账单、日志、变更分别取证，账号存在不等于全部就绪 |
| 内置指标 | 部署随附 VictoriaMetrics | 有实际指标且目标查询成功 |
| 外部指标 | 数据源 / 集成配置 | 探活之外，还需核对是否进入目标查询、巡检或诊断 |
| 日志 | SLS 隐式源或已配置日志源 | 目录、角色、采纳验证和实际内容查询分别完成 |
| 变更 | 云拉取源或应用 webhook | 拉取 adapter 与推送事件分开，验证去重和持久化 |
| 虚拟化 / 数据库 / 其他 | 云账号或数据源登记 | 探活不等于完整清单、历史数据或统一诊断 |

## 当前支持矩阵

| 来源 | 当前实现 | 验证边界 |
|---|---|---|
| 阿里云 | 资产、指标、SLS、账单、ActionTrail 等深度路径 | 当前真实证据主要限定于指定只读账号与已记录范围 |
| 腾讯云 | 存在部分资产、账单、CLS 等代码路径 | 当前无测试账号的新一轮真实验证，不写成已真实打通 |
| 其他云厂商 | 部分 adapter 或知识包扩展契约 | 没有当前真实连通和资产证据时不算生产支持 |
| vCenter / ESXi | 有版本探测、清单和基础指标代码 | 具体验证范围以 [capabilities.md](capabilities.md) 为准，不自动执行外部操作 |
| VictoriaMetrics | 内置指标底座 | 本机开发与 Compose 端口见 [deployment.md](deployment.md) |
| Prometheus / 外部 VM | 可注册 Prometheus 兼容端点 | 指定测试场景不等于统一告警、巡检、画像或诊断已接入 |
| SLS | 隐式源、完整目录、角色推荐、采纳验证和统一查询 | 未配置索引和未知角色保留缺口，不自动创建索引 |
| Loki / Elasticsearch | 有查询适配 | 指定测试机做过限定真实场景，不证明所有语义与告警闭环 |
| 腾讯云 CLS | 有 SearchLog 检索 / SQL 适配代码 | 当前未做真实账号复验 |
| VictoriaLogs | Compose 部署预留 | 不是已实现的统一日志查询能力 |
| ActionTrail | 内置通用拉取变更源之一 | 有指定账号真实只读归一化证据 |
| Git webhook | 有推送事件接收入口 | Gitea 指定场景验证不代表所有 Git 平台与事件 |
| SkyWalking / Zipkin | webhook 写变更事件 | **不创建完整告警处理记录，不做全量 trace 分析** |

## 日志边界

- 统一日志查询消费已配置日志源和有效阿里云凭证形成的 SLS 隐式源。
- SLS 旧调用路径保留兼容；K8s 容器日志有独立入口，不伪装成已进入同一查询层。
- 原始日志不得持久化到接入 Run、模型走查 artifact 或公开文档。
- 未知日志角色不自动绑定；业务归属不按名称相似度猜测。

## 指标与探活边界

- 探活应取得版本或系统信息，不以端口开放或 HTTP 200 代替。
- 探活与查询适配解耦；登记型数据源不能显示成统一查询已可用。
- InfluxDB、Graphite、OpenTSDB、自定义 HTTP 等部分类型只有登记或探活。
- 外部 Prometheus/VM 注册源不能据此宣称进入所有内置消费面。

## 扩展新源

1. 先明确用户任务需要哪类数据，不先增加“已配置”卡片。
2. 复用现有数据源、账号上下文、变更源或日志适配接口。
3. 分别定义探测、清单、查询、历史回填、权限和失败语义。
4. 无权限、无数据、部分失败和不支持分别呈现。
5. 用真实只读数据完成内容级验证后，才更新“真实验证”标签。
6. 新运行时 Skill/MCP 资源写入 `agent/`，不要在 `docs/` 新建平行知识目录。
