# FIRST-USE：授权接入与首次价值

## 1. 任务 ID、状态、最近确认日期

- 任务 ID：`FIRST-USE`。
- 状态：用户已于 2026-11-17 批准实施；按 `O1 → O2a → O2b → O2c → O3` 顺序执行，界面依赖 `CONCISE-INTERACTION`。
- 最近确认日期：2026-11-17。
- 本契约只定义接入与首次价值；当前完成证据仍以 [../capabilities.md](../capabilities.md) 和 [../status.md](../status.md) 为准。

## 2. 用户从哪里开始，最后必须得到什么结果

用户从安装后的阿里云授权入口或既有账号的“继续接入”开始，提交满足任务范围的最小只读凭证并完成既有安全确认。平台自动准备后，按已有数据给出至少一个可核查结果：费用及覆盖期、已回读指标及资源范围，或已确认日志的一次受支持分析。

只有资产清单时，只显示“已发现资源，分析数据仍在准备”，不算首次分析价值达成。未识别完全部日志不得阻塞已经可用的费用、指标或变更结果。

## 3. 本期范围与明确不做

- 首期仅覆盖阿里云新账号，以及用户主动继续接入的既有账号；复用资产、CMS、SLS、BSS、ActionTrail 路径。
- 保留现有 Onboarding Run、后台调度、数据库和部署架构，不新增第二套任务引擎。
- 不扩展其他云厂商，不改变 Kubernetes、虚拟化和既有高级入口行为。
- 不自动购买、开通收费服务、创建索引、修改云资源或发送真实外部通知。
- 不把升级安装视为批量重扫存量账号的授权，不覆盖已确认的日志与业务映射。
- 不扩展多主应用日志消费模型，不承诺识别所有日志或推断真实业务归属。

## 4. 自动步骤与人工确认点

平台自动验证凭证、发现资产、读取账单、验证指标写入与回读、发现日志、读取受控变更窗口，并按能力独立记录进度。暂时性错误按退避最多重试三次；403、缺索引和明确未开通不反复重试。重试只处理失败或未完成范围，保留成功结果，进程重启后恢复为可重试状态。

用户只负责提供合规只读凭证、完成安全确认，以及集中确认确有歧义的日志角色或链路位置。候选不唯一、证据不足或类型不受支持时允许“不确定”和稍后处理；平台不得静默取第一条。

## 5. 数据来源、身份、状态与失败契约

每项能力使用 `assets | metrics | logs | cost | changes` 标识，并在现有 Run 的结构化证据中记录：显式 `account_id`、厂商、地域、来源和适用资源身份；`execution`、`data_state`、覆盖计数、检查时间、数据截止时间、证据引用、原因码、可重试性和下一步。旧 Run 缺字段一律为“未验证”。

- 执行成功只代表读取或处理成功；空结果为 `no_data`，不得推出零费用、无变更或健康。
- 分母未知时显示“范围未完整获取”；分页失败或截断必须保留完整未完成清单。
- 身份缺失、账号停用或凭证解密失败时 fail closed，不回退首账号。并发执行在线程内建立独立数据库 Session 和账号凭证上下文。
- 首次账单先取最近一个可查询账单日，再后台补最近 30 天；逐日保留成功、空数据、失败和摊销缺口，禁止附带采购、包快照和通知。
- 指标必须验证落库与回读，资源身份不唯一时不得用于账号级结论；VM 不可用不就绪。
- 日志先完整分页目录，再按近期 24 小时、每个 Logstore 最多 5 条有界采样；原始日志不落 Run、不进入模型。
- 日志采纳前验证和采纳后消费必须使用同一账号、endpoint 和已确认字段映射；不支持时明确停止语义分析。
- 变更空窗口、无权限和截断分别呈现，空事件不等于近期无变更。
- 状态读取不得触发云调用；锁占用显示等待，不能借用上次成功结果。

## 7. 正向场景与禁止结果的反例

正向场景：有效凭证提交后，各数据面独立推进；用户刷新或换入口仍看到同一 Run，并在任一能力证据充分后获得带范围、时间和证据的结果。

禁止结果：

- “保存凭证成功”被当作“费用可分析”。
- “无数据”被当作零费用、近期无变更或环境健康。
- “上百个日志源已发现”被当作“全部业务日志已理解”。
- 200 个合成 Logstore 隐藏尾页，重名或多候选自动选错，失败组合半写配置。
- 自定义 endpoint 在验证和消费阶段不一致，或不支持的字段仍假设为 `LogLevel`。
- 一面 403 阻塞其他面，重试重跑成功项，晚到响应覆盖较新的任务结果。
- viewer 能启动任务；凭证进入模型、Run、日志、浏览器持久存储或回显接口。
- 真实外部写或通知在测试和新手接入中发生。

## 8. 验证等级及发布条件

先写失败用例，再最小实现并运行本契约关联的隔离测试；随后运行 `CONCISE-INTERACTION` 的跨入口浏览器验收和前端构建。测试使用临时库、假凭证及云 SDK/通知替身，真实外部写与通知调用次数必须为零。

只有在用户明确授权的账号、日期和查询量范围内完成真实只读验证后，才能标记“真实验证”。未获授权时只能写“隔离验证通过，真实首次使用待验”。发布还要求：首次改密后的必要操作不超过提交凭证、安全确认和必要时一次集中日志确认；首个有效结果出现后其余任务可继续，且完整失败清单没有丢失。
