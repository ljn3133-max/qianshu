# CONCISE-INTERACTION：共享任务结果卡与简洁交互

## 1. 任务 ID、状态、最近确认日期

- 任务 ID：`CONCISE-INTERACTION`。
- 状态：用户已于 2026-11-17 批准；在 `FIRST-USE` 的 O1/O2/O3 后，按向导、云账号页、智能体顺序交付 U1，并为 C2 提供共享结果卡。
- 最近确认日期：2026-11-18。
- 实施状态：U1 代码与隔离验收完成，共享受理提示和高级折叠区样式契约已覆盖；真实首次使用与新手走查待验，隔离结果不替代发布条件。
- 本契约只规范共享交互和任务引用，不另建任务引擎、聊天页或成本计算逻辑。

## 2. 用户从哪里开始，最后必须得到什么结果

用户从安装向导、云账号页或智能体进入同一接入任务，看到一句当前结论、最多三个关键数字、最多三个阻塞摘要和一个主动作；需要时展开完整证据与失败清单。离开、刷新、重新登录或网络恢复后仍继续原任务。

成本首屏复用同一结果卡展示三个答案，但成本事实只能来自 `COST-INSIGHTS`。长报告保留为“详细报告”，不得作为默认正文。

## 3. 本期范围与明确不做

- 新增共享任务结果卡和受保护云凭证表单，依次接入向导、云账号页和智能体。
- 新手主线合并为授权接入、自动准备、查看结果；其他环境和高级字段折叠，原高级入口保留。
- 智能体返回结构化任务引用，页面跳转携带账号、对象、时间窗和证据引用。
- 不新增独立聊天页或任务管理平台，不用 Markdown 机械截字生成短卡。
- 不降低既有服务端安全确认强度，不隐藏必要授权、收费风险和范围提示。
- 不修改 Kubernetes、虚拟化、其他云厂商接入行为，不增加外部通知动作。

## 4. 自动步骤与人工确认点

平台自动恢复同一 Run、合并重复进度、按能力选择主动作，并只在需要人处理或结论变化时突出提醒。模型配置不作为基础接入前置条件；无模型时仍展示确定性发现、状态和费用卡。

用户只在提交凭证、安全确认、处理必要授权和确认真实歧义时操作。凭证无效时在当前卡修改并继续同一账号、同一任务；viewer 只能查看证据，需要管理员处理的动作明确标出，不展示可执行假按钮。

## 5. 数据来源、身份、状态与失败契约

接入卡只消费 Onboarding Run 的能力结果，成本卡只消费成本洞察服务；前端不得自行拼接另一套执行状态、覆盖率或成本数字。

- 所有请求和跳转显式携带账号、Run/任务引用及适用范围；晚到响应不得覆盖新账号或新任务。
- 同一任务更新原卡，不连续追加重复进度消息；完整失败清单可展开，不因主卡最多三条而丢失。
- 无云凭证时提供“请管理员授权”短卡，包含最小只读权限、官方入口和可复制申请内容。
- 凭证只进入受保护结构化表单并直接提交后端；退出后清空明文，不进入聊天、模型、Run、日志、浏览器持久存储或回显接口。
- `init_done` 只控制向导路由，不显示无范围“全部就绪”。无数据、失败、未执行和部分可用必须可区分。
- 过期会话和网络失败保留可恢复任务身份，错误信息不得泄露秘密。

## 7. 正向场景与禁止结果的反例

正向场景：一次提交后两秒内显示已受理和任务身份；刷新、切入口和网络恢复后继续同一任务，账号切换只展示当前账号结果。首个可用能力即可成为主动作，其余能力继续准备。

禁止结果：

- 新手仍被要求手动测试、同步、体检或先配置模型。
- 保存账号后显示无条件“全部就绪”，或只有资产清单就宣称首次分析价值达成。
- 两秒受理目标被写成两秒完成云扫描的承诺。
- 主卡堆满内部步骤、SQL、参数名、大段安全说明或长报告；必要授权与范围提示被藏进折叠区。
- 失败清单因摘要最多三条而截断丢失；连续轮询追加重复卡片。
- 晚到的账号 A 响应覆盖账号 B；快速切账号或连续点击创建重复任务。
- 密钥粘贴到聊天、写入浏览器持久存储或由接口回显；viewer 看到可执行假按钮。
- 页面跳转只发送“帮我分析费用”，缺少结构化范围和证据。

## 8. 验证等级及发布条件

先以隔离后端和合成数据验证三入口共享状态、凭证不泄露、viewer 权限、晚到响应、刷新恢复和模型不可用降级，再执行前端生产构建及独立 Chrome 会话验收。两秒只验证受理响应目标，不承诺云扫描完成。

真实新手体验需由目标用户独立走查；测试人员不得现场解释云术语。未执行真实环境或用户走查时，分别保留“真实首次使用待验”和“新手走查待验”，不得以页面渲染或接口 200 代替。发布前所有中英文文案、深链、原高级入口和完整失败清单必须保留。
