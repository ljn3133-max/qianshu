## 2. 用户从哪里开始，最后必须得到什么结果

用户从成本页或携带完整账号、对象、时间窗和证据引用的智能体入口开始，默认获得三个答案：钱主要花在哪里、哪里不正常、现在先做什么。每个答案都能展开到对应产品、实例或计费项的实际值、基线、时间窗和来源。

没有可靠建议时，最终结果是“当前证据不足以形成优化建议”，不是强行生成动作。没有异常时只能说“在已验证范围内未检出异常”。

## 3. 本期范围与明确不做

- 新增本地只读成本洞察服务，默认最近 30 天、截至昨日；页面与智能体共用同一结果。
- 首期建议仅限排查异常增长、核实首次观察费用、评估持续高额按量支出。
- 原费用图表、明细、深链和资源包高级入口保留，但不要求新手先理解资源包。
- 不恢复采购登记、核价、净节省、购买数量、SKU 推荐或买后复盘。
- 不迁移历史异常生命周期，不重启全仓账号模型改造，不增加汇率换算。
- GET 不触发云同步、外部写入或通知；不自动执行优化或处置云资源。

## 4. 自动步骤与人工确认点

确定性代码负责账号范围、账单口径、覆盖判断、金额计算、同口径基线、贡献定位和候选排序。模型只解释已结构化的事实和证据；模型不可用时，费用概览与事实卡仍可使用。

用户负责判断业务必要性、预算、风险容忍度及后续采购或处置。平台最多给三条有证据的建议，按证据充分、影响金额、处理风险和稳定标识排序；金额缺失不编造排序分值。

## 5. 数据来源、身份、状态与失败契约

`GET /api/cost/insights` 必须显式接收账号和日期范围，只读本地已采集证据。默认显示当前接入账号；查看全部账号时分账号呈现，缺少归属的数据不得算入任一账号。

- 请求区间与实际覆盖同时返回，历史不足不得静默缩短后声称完整。
- 日成本沿用 `total = payg + amortized`；订单和退款另列，不再次加进日成本。
- 对应金额使用 `pretax_amount`；不得以 `payment_amount=0` 推断免费或已抵扣。
- 缺摊销时明确“当前仅含已获取部分”；未取到数据用空值与原因表达，不用零兜底。
- 真实零费用必须有成功采集和完整范围证据；费用结果带账单日和采集时间。
- 基线来自同账号、同计费项和可比较日期，复用现有周期基线算法；冷启动不套用旧兜底制造异常。
- 新增费用需要历史覆盖证明，否则降级为“首次观察”，不得声称刚开通服务。
- 按账号原始账单复算异常，不把全局聚合异常行筛选后当作账号级证据。
- 每条结论带来源、范围、时间、证据和白名单下一步；`estimated_savings` 保持空值。

## 7. 正向场景与禁止结果的反例

正向场景：同账号、同窗口下，页面与智能体返回相同数字、状态和证据，且页面汇总能与原始明细对账；点击结论可定位具体对象、时间、金额和依据。

禁止结果：

- 按量 100、摊销 20、订单 500 的合成场景日成本为 620；正确结果必须为 120。
- “无数据”被当作零费用或健康，缺摊销被当作完整总花费。
- 冷启动宣称异常或新费用，零基线被强行判异常，账单修订造成重复计费。
- “指出高额按量支出”被转换成“应买指定资源包”，或返回未经核价的节省金额。
- 没有用量证据仍判断单价或用量原因，没有建议时强行凑满三条。
- “页面与模型说法相同”被当作数字正确；两者必须共同回溯到 C1 和原始账单。
- 模型超时导致确定性结果消失，切账号后旧卡仍显示，或只向智能体传一句自然语言问题。

## 8. 验证等级及发布条件

C1 分两步做内容级隔离断言：先验证成本、覆盖和排行，再验证异常、首次观察和按量候选。缺摊销、无账单、退款、真实零费用、零基线、账单修订、历史不足和账号切换必须分别断言。C2 还需前端构建、模型超时降级和真实 Chrome 证据链检查。

真实环境只读查询必须由用户明确授权账号、日期和查询量；无授权时只标记“隔离验证通过，真实成本任务待验”。发布前由五名未使用过平台的目标用户走查，至少四名能在一分钟内说出最大支出项、需要关注的变化和建议下一步；不得由测试人员现场解释云术语。建议至少定位具体对象、时间、金额和可核对依据，不以异常数量或节省金额凑指标。
