## 证据等级

| 标记 | 含义 |
|---|---|
| 真实验证 | 在真实应用或指定测试环境完成内容级验证，仅限记录范围 |
| 隔离验证 | 临时库、mock 或隔离服务通过，不证明外部环境可用 |
| 代码支持 | 源码存在实现，不能据此宣称端到端任务已验证 |
| 设计 / 未实现 | 方案、预留或缺失能力，不是已交付功能 |

接口 200、页面渲染、mock 全绿、组件启动或文档存在都不等于用户任务闭环。

## 目录治理（2026-11-17 用户确认）

```text
docs/
├── active/    # 唯一真相源；改代码前按任务必读
├── archive/   # 只读历史；只有用户明确指定时才读取
└── tmp/       # 运行产物；用完即弃，不进版本控制和上下文
```

### 写入规则

1. 新文档一律放入 `active/`，除非明确是归档材料。
2. 需求变更时，旧版文档移入 `archive/`，不在 `active/` 保留历史版本。
3. 用户口头确认的决策必须写入 `active/` 对应文档，不能只停留在对话中。
4. 代码改动与文档不一致时，必须同步更新文档。
5. 验收摘要、对比截图和临时分析只能进入 `tmp/`，不得写入 `active/` 或 `archive/`。

### 读取规则

1. 默认只读取 `active/` 下的具体文档。
2. `archive/` 仅在用户明确要求排查历史决策时读取。
3. `tmp/` 不进入上下文，除非用户显式指定。
4. 不一次性扫描整个 `docs/`，不用 `archive/` 作为当前实现依据。

### 禁止行为

- 禁止在 `active/` 保留已被替代的旧方案或复制一套平行 Wiki。
- 禁止生成大量验收摘要、对比截图等中间产物存入文档树。
- 禁止在对话中引用 `archive/` 内容作为当前实现依据。
- 禁止仅因历史文档存在就重复迁移、重复验收或恢复已回滚功能。

历史文件原名与内容索引见 `archive/README.md`，但默认不读取。参与贡献请先阅读根目录 `CONTRIBUTING.md`。
